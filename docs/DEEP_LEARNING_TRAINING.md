# Deep Learning Training: RNN and LSTM

## Notebook

Open `model_API/notebooks/RNN_LSTM_Medical_Classification.ipynb` after starting Jupyter from the project root:

```powershell
.\.venv\Scripts\python.exe -m jupyter lab
```

The notebook follows this architecture:

```text
Symptoms -> token IDs -> Embedding -> RNN or LSTM -> Dropout -> Dense condition labels
```

It trains on `dataset/usable_dataset.csv` and saves:

```text
model_API/checkpoints/deep_learning/
  rnn/epoch_001.pt ... best.pt
  lstm/epoch_001.pt ... best.pt
```

Each folder also contains `vocabulary.json` and `training_metadata.json`. The Flask API loads `best.pt`. If a checkpoint is missing, the Streamlit model option explains how to train it instead of returning an ungrounded result.

## Honest evaluation boundary

The base dataset has one NHS source document per condition. The pipeline creates overlapping chunks from each condition’s symptom text. Consequently, its held-out chunk metrics measure within-document engineering behaviour, not independent patient performance, clinical safety, fairness, or diagnostic accuracy.

Medical fields shown in the UI are still retrieved from the local RAG knowledge base rather than generated by the model.

The API applies a quality guard to the current experiment: until the held-out chunk Top-1 score reaches 20%, RAG's top local match remains the displayed condition and the RNN/LSTM ranking is retained only for evaluation. This prevents a weak checkpoint from overriding the knowledge-base retrieval result.
